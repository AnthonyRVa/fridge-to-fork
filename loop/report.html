The loop prompt

The goal, checklist and stopping rule Claude worked from:

Run a quality loop on Fridge to Fork's recipe search. Test set: 8 realistic fridges (breakfast leftovers, chicken & rice, pasta night, fish dinner, plant based, mezze, diner, taco Tuesday) × 8 cuisine choices (any, Mexican, Latin American, Asian, Italian, Mediterranean, Indian, American) = 64 combinations, run against the real TheMealDB data. Every combination must pass: 1. At least 3 useful recipes (each uses 2+ fridge items). 2. When a cuisine is chosen, at least 3 of them in that style; if not, the page must say so. 3. The top pick is sensible: needs at most 5 store items (no style chosen), or is the in-style recipe that needs the fewest. 4. No false ingredient matches (having "chicken" must not tick off "chicken stock"). Each round: run the test, group the failures, fix the biggest cause in the code, re-run. Tell apart failures caused by our code and failures caused by recipes the database doesn't have. Stop when only database limits remain or a round stops improving, at most 10 rounds. After the loop, deploy and re-run the Playwright browser test on the live site.
